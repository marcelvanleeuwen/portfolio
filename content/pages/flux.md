# RunOnFlux

I have been running FluxNodes for several years. They run in production as part of my homelab and provide server resources to the Flux network. This page explains what the project does and why I take part in it.

## What is Flux?

[Flux](https://runonflux.com/) is a cloud computing project. People use it to host websites, applications, and other services. The hardware comes from independent server owners around the world.

With a traditional cloud provider, you rent resources from one company. Flux takes a different approach: many operators contribute their own servers to a shared network. This is what the project means by a decentralized cloud.

## How does FluxCloud work?

FluxCloud is the part of the project used to deploy and manage applications. It supports Docker containers, so developers can package their application with the software it needs to run.

The network places these applications on FluxNodes. Applications can run on several nodes, which helps keep them available if one server goes offline. The exact setup depends on the application and its needs.

There is also a marketplace with ready-made applications. This gives users a starting point without having to build every container themselves. You can explore it on the [FluxCloud website](https://cloud.runonflux.com/).

## What is a FluxNode?

A FluxNode is a server that contributes processing power, memory, storage, and network capacity. Together, these servers provide the hardware behind FluxCloud.

Nodes must meet the network's hardware and connection requirements and pass performance checks. Operators need to keep their systems online and working properly. In return, eligible operators receive rewards in FLUX, the project's cryptocurrency.

The official [FluxNode documentation](https://docs.runonflux.com/fluxnodes/what-are-fluxnodes/) explains the node types, software options, and requirements. I use the official documentation for current details because these can change.

## Why I run FluxNodes

I like working with servers, Linux, networking, and containers. Running FluxNodes lets me use those skills to support a network that hosts other people's applications.

My nodes are part of my production setup. Keeping them online, checking their status, and looking after the systems is part of managing my homelab. I enjoy the practical side of it: setting things up, solving problems, and learning how the different parts work together.

## Game servers on Flux

Flux also offers [game server hosting](https://runonflux.com/games/). You can rent a server for a group of friends or a gaming community, without running the game server on your own PC at home.

Some examples are:

- **Minecraft:** Java and Bedrock servers, with options for mods and plugins on Java.
- **Palworld:** a shared world for up to 32 players.
- **Valheim:** a survival world with support for Xbox and Game Pass crossplay.
- **Rust:** standard or modded servers, with tools to manage players and settings.
- **Terraria:** servers with TShock admin tools and plugin support.
- **FiveM:** GTA V roleplay servers with txAdmin and a MySQL database.

There are more games too, including Project Zomboid, Enshrouded, Satisfactory, and Factorio. The [games page](https://runonflux.com/games/) has the full list, plans, and setup guides.

You choose a game, a plan, and a server region. The dashboard lets you manage the server, and backups are included. Features such as mods, crossplay, and player limits depend on the game and plan. Choosing a region near your players can help reduce lag.

These game servers use the same Flux network as other applications. I like this as a practical example of what the project does: people can use the network to play together, while node operators provide the hardware behind it.
